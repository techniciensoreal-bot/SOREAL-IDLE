# Audit de la progression hors ligne : jeu (build 1260) contre moteur SOREAL

Date : 2026-11-16. Source jeu : IL de `Assembly-CSharp.dll` (ids entre parenthèses). Source SOREAL : `cloudflare/src` (aucun fichier modifié). Rien n'est tiré du wiki ni de la mémoire : tout nombre du jeu est lu dans l'IL.

## 0. Mécanisme du jeu (lu)

- Appelants : `OpenFileDialog::loadintoGame` (4693), `LoadText` (5288), `getLoad` (5324), `getAGLoad` (5330). Écart = `Epoch::SecondsElapsed(character.lastTime, Epoch::Current)` = valeur absolue de la différence (4479), entier. `lastTime` est écrit à chaque sauvegarde.
- Règle (identique dans les trois chemins principaux) : `secs = max(0, écart)` ; `secs = min(secs, 31 536 000)` ; **appel seulement si `secs > 10`**. **Plafond = 1 AN (365 j). Aucun plafond de 24 h / 72 h, aucun bonus de durée n'existe dans ces chemins.** Seule exception : un rechargement d'ancienne mise à jour (`ignoreOfflineProgress`, message « toss your offline progress ») jette tout.
- `Character::addOfflineProgress(secs)` (2231) : une seule passe, des formules fermées avec les stats du moment du retour (aucune simulation seconde par seconde), dans cet ordre :
  1. au tout début : `loc0 = clamp(secs - ceil((capEnergie - énergie) / énergieParSeconde), 0, secs)` (secondes passées barre pleine) et `loc1` identique pour la magie (le jeu utilise `energyPerSecond`, pas `magicPerSecond` : bug du jeu) ; `daily.spinTime += secs` borné à `maxSpinTime` (129 600 s ; 604 800 s avec la banque 7 j) ; minuteur du Muffin retiré de `secs` (plancher 0) ;
  2. sorties immédiates SANS RIEN avancer : défi 100 Levels, Troll, 24 Hour (messages « No Offline Progress ») ;
  3. `rebirthTime`, `totalPlaytime`, `dailySaveRewardTime`, `pit.pitTime` + `secs` ;
  4. dans l'ordre : `makeOfflineEnergy` (2232), `Magic` (2233), `Res3` (2234), **`Gold` (2235)**, `training` (2236), `wandoos` (2242), `augment` (2243), `bloodMagic` (2244), `advancedTraining` (2246), `timeMachine` (2245), `questing` (2238), `adventure` (2239), `inventory` (2241, garderie d'objets), `yggdrasil` (2247), `ngu` (2248), `beard(loc0, loc1)` (2249), `hacks` (2250), `wish` (2251), `cards` (2252), `cooking` (2253) ; puis les minuteurs de défis actifs avancent de `secs`.
- Systèmes qui NE progressent PAS hors ligne dans le jeu : Auto Merge / Auto Boost, Diggers (aucune production propre, mais leur drain réduit l'Or), Money Pit (seul `pitTime` avance), effets des potions/charmes/Bar Bars (les vitesses sont DIVISÉES par `potionModifier` : pénalité), minuteurs des potions (ils ne baissent pas ; seuls le Muffin et le Mayo Infuser baissent), installation de Wandoos 98 (voir §3), farm de zone d'Aventure (n'existe pas), butin d'objets (Titans et ITOPOD).

## 2. Écarts priorisés avec correctif exact

### P1 (effet joueur significatif)

**E1. Or hors ligne : ordre et niveaux utilisés** (`idle-ngu-systemes.js:1436` `passesDuTempsSeulV1`, `idle-ngu-pistes.js:965-1075`).
Jeu : l'Or `goldPerSecond(niveaux d'avant) x secs` est crédité en TÊTE, puis Augmentations, Blood Magic, Time Machine l'utilisent (dans cet ordre de priorité sur l'Or : Augmentations, Blood Magic, Time Machine vitesse puis multiplicateur). SOREAL : Augmentations tournent AVANT le crédit (elles ne voient que l'Or d'avant l'absence), Time Machine achète avec l'Or d'avant, crédite à la fin avec le gps d'APRÈS ses nouveaux niveaux (plus généreux), Blood Magic vient après.
Correctif : dans `advanceIdleNguState`, quand `secs` est en mode hors ligne (même seuil que le reste : `secs >= 300`, ou tout `secs > 10` pour coller au jeu) et `bosses >= 30` et Time Machine débloquée et pas de défi Time Machine : calculer `gpsAvant = idleNguTimeMachineGoldPerSecond(state)` AVANT toute passe, créditer `state.currencies.gold += gpsAvant * secs` (et `producedThisRun`), puis exécuter les passes dans l'ordre du jeu (ressources, Wandoos, Augmentations, Blood Magic, Entraînement avancé, Time Machine, Yggdrasil, NGU, barbes, hacks, souhaits) et supprimer le crédit final de `avancerTmGrossierV1` (lignes ~1065-1070) pour ce mode. Test : une partie avec Or = 0, Time Machine active et 1 h d'absence doit acheter le même nombre de niveaux d'Augmentation que la formule du jeu.

**E2. ITOPOD hors ligne** (`idle-ngu-systemes.js:869-1010`).
Jeu : étage unique = `min(calculateBestItopodLevel, highestItopodLevel)`, plages départ/fin ignorées, jamais de nouvel étage ni de PP de première atteinte ; kills = `floor(secs / (1 + respawnTime()))` ; boosts seulement avec le filtre cube, en puissance de cube déterministe.
Correctif (mode hors ligne, `secs >= 300`) : forcer `start = end = min(optimal, d.highestFloor)` (sans `reachFloor`), ignorer `d.startFloor/endFloor/shifter` ; remplacer le tirage de boosts (14 %) par : si `state.adventure.cubeFilter` (réglage « Filter Boosts into Infinity Cube »), `cubePower += capAttack[tier] x kills / 8 x boostBonus / (((perk 26) ? 50 : 100) / diviseurSouhaits x 2)` (idem robustesse) et AUCUN objet de boost sinon. Garder tier / killsPerAP / EXP (déjà identiques). Écart d'arrondi secondaire : le jeu fait `kills / killsPerAP` en division entière par session (reste perdu) ; SOREAL reporte le reste (négligeable).

**E3. Barbes : secondes passées barre pleine seulement** (`idle-ngu-pistes.js:192-261`, `idle-ngu-systemes.js:1436`).
Jeu : `tempsPlein = clamp(secs - ceil((cap - courante) / ressourceParSeconde), 0, secs)` calculé AVANT la production de l'absence ; les barbes d'énergie utilisent `tempsPleinÉnergie`, celles de magie `tempsPleinMagie` (calculé avec `energyPerSecond`, bug du jeu).
Correctif : avant `advanceGeneratedResources`, mesurer `tpE`, `tpM` (formule ci-dessus) et les passer à `advanceTrackSystem` pour `beards` à la place de `seconds` ; en conservant le garde-fou du jeu `niveaux <= max(tpE, tpM) x 50 x 1,01`. Aujourd'hui, comme la ressource est déjà pleine après la passe de génération, SOREAL compte TOUTE l'absence.

**E4. Titans hors ligne** (`idle-adventure-combat.js:340-455`, `idle-ngu-systemes.js:1210`).
Jeu : (a) aucun Or ; (b) EXP par kill = `bossNExp x facteur 24 Hour` (+50 % perk 34 sur `3 x niveau` premières victoires, et seulement si ce nombre est entre 1 et 9), pas de facteur « souhait 3 / palier » ; PP des titans 6 à 12 = `bossNPP` ; AP seulement titans 1 à 5 (`boss1AP`..`boss5AP`) ; (c) seuils : puissance ET défense ET régén (`totalAdvHPRegen`) : titans 4 (14 000), 5 (150 000), 6 à 12 : V1 uniquement (6 : 2,5e9 / 1,6e9 / 2,5e7), le palier de récompense est celui choisi par le joueur (`titanNVersion`) ; (d) aucune case « Automatically Kill Titans » n'est lue ; (e) temps de respawn d'Amalgamate : 27 000 s de base (SOREAL : `(433+1/3)/60 h` = 26 000 s, `idle-adventure-zones.js:665`).
Correctifs : retirer `out.gold` des kills hors ligne (garder l'Or pour les combats manuels / en ligne) ; ne pas appliquer `rewardMult` du souhait 3 quand `!ctx.enLigne` ; exiger `regen >= seuilRégén` (valeurs : t4 14 000, t5 150 000, t6 V1 2,5e7 / V2 2,5e8 / V3 2,5e9 / V4 2,5e10, t7 5e12 / 1e14 / 2e15 / 5e16, nerd 5e16(=8V1) etc. : relire 183-227) ; corriger `amalgamate.cooldown` à `7.5*H` (27 000 s). La case par titan (Norman 2026-10-10) et l'alternative « N victoires » sont des choix SOREAL : à valider (le jeu ne les a pas) ; plafond de 2 000 cycles à relever si l'absence passe à 1 an (un titan de 1 h donne 8 760 kills).

**E5. Entraînement avancé : cible non bornée hors ligne** (`idle-ngu-pistes.js:480-497`).
Jeu : `levels = min(scaledLevelGain, targetLevel - niveau)` (rien si `targetLevel <= niveau`, hors souhait 190). SOREAL gagne tous les niveaux de la fenêtre puis `atApplyTargetsV1` retire l'énergie : une cible 100 peut être largement dépassée après plusieurs heures. Correctif : dans la boucle `for (const trackDef of tracks)`, `gained = Math.min(gained, Math.max(0, cible - level))` quand `t.target > 0`, et ne pas remettre `t.progress` à `step.p` si le plafond a joué (barre à 0), comme `advanceTrackSystem` le fait déjà pour les autres pistes (ligne 669).

**E6. Hack final hors ligne à demi-vitesse** (`idle-ngu-etat.js:1259`).
Jeu : `progress += endHackSpeed x secs x 50 / 2` (2250) ; en ligne `1e-7` par tick = 200 000 s. Hors ligne : 400 000 s. Correctif : en mode hors ligne (`seconds >= 300`) ajouter `seconds / 2` au lieu de `seconds` à `d.finalHackSeconds`.

**E7. Plafond de 30 jours au lieu d'un an** (`idle-hors-ligne-v1.js:6`).
Jeu : 31 536 000 s. Correctif : `PLAFOND_HORS_LIGNE_SECONDES_V1 = 365 * 24 * 60 * 60`. À mesurer d'abord : plusieurs boucles de SOREAL ont des garde-fous (`3 000 000` niveaux d'Augmentation, `1 000 000` rituels, `20 000` tours ITOPOD, 2 000 cycles de Titan, garderie, etc.) qui peuvent tronquer silencieusement une absence de 1 an (perte, jamais gain) ; le jeu n'a aucun garde-fou de ce genre. Un durcissement pourrait demander de passer ces boucles en formule fermée. Seuil à 10 s : sans effet (les synchros en ligne font ~15 s).

### P2 (écarts mineurs ou à décider)

**E8. Seuil « hors ligne » 5 min au lieu de 10 s** (`idle-ngu-systemes.js:1464`, `1247`, `1500`) : le jeu retire l'effet des potions / charmes / Bar Bars et le farm pour tout écart > 10 s. SOREAL attend 300 s (parce que chaque synchro en ligne est un « delta »). Sans conséquence jouable (un retour à moins de 5 min peut garder une potion active : au maximum 5 min d'avantage).

**E9. Wandoos 98 : installation de 24 h** : le jeu exige `installTime >= 86 400` (compté à 0,02 s par tick, seulement en ligne : 4779) avant tout effet ; hors ligne, `installTime` n'avance PAS. SOREAL n'a aucune notion d'installation. À confirmer avec le wiki / Norman : si l'installation de 24 h existe réellement pour le joueur, SOREAL donne Wandoos immédiatement. Boot : le jeu applique la vitesse de boot de la FIN de l'absence à toute la fenêtre ; SOREAL moyenne la rampe (moins généreux) : pour coller, `bootFraction = clamp(elapsedFin / bootSeconds, 0, 1)` sur la fenêtre entière.

**E10. Hacks : un seul hack actif** (`idle-ngu-pistes.js:603`) : le jeu fait progresser TOUS les hacks ayant du R3 alloué ; SOREAL n'avance que `activeTrack`. Écart de conception en ligne comme hors ligne, hors du périmètre strict de cette mission (à confirmer dans `HacksController::updateAllHacks` 3194, qui boucle bien sur tous les hacks).

**E11. Chronologie des Titans** : cooldowns du No Rebirth Challenge : le jeu retire `900 s x complétions` (plafond propre à chaque titan : 3 600, 3 600 (t3/t4), 7 200 (t5), 9 000 (t6), 12 600 (t7), 14 400 (t8), 16 200 (t9), 19 800 (t10), 21 600 (t11), 23 400 (t12)), plancher 3 600 s ; Évil / Sadistic comptent à partir de t7. SOREAL utilise trois variables de réduction globales (`titanCooldownReductionMs...`, `idleAdventureTitanCooldownMsV1`). NON VÉRIFIÉ numériquement.

**E12. Farm de zone d'Aventure hors ligne** : invention SOREAL (déjà `aventure.md`, point 15 ; au registre).
